Капани — новая платформа посёлка

Статический фронтенд находится в public. Его можно разместить в подпапке GitHub Pages. Серверная логика находится в SQL-миграциях Supabase; собственный постоянно работающий Node-сервер не требуется. Это рабочая незавершённая сборка. Фактический статус и ограничения описаны в docs/STATUS.md.

Для локальной разработки установите Node.js 22 или новее, выполните npm ci, npm run build и npm test. Публикуйте содержимое public как статические файлы. В среде Sites предварительный просмотр запускается командой sites-preview start с абсолютным путём проекта. На GitHub Pages нужен HTTPS, правильная подпапка и разрешённый URL возврата в настройках Supabase Auth. В public/js/config.js разрешены только URL проекта и publishable key. Секретный или service-role ключ в браузере запрещён.

Новая база этого проекта имеет идентификатор svxgjisrkagmqjamnexp. Применяйте SQL из supabase/migrations в порядке имён только к заведомо чистой базе. Исходные миграции намеренно останавливаются при конфликте таблиц и не сливают неизвестные данные. При развёртывании другой чистой среды сначала проверьте её идентификатор и историю миграций, затем примените каждый файл один раз. Повторяемость обеспечивается журналом миграций, а не разрушительным пересозданием таблиц. В текущем новом проекте 20 миграций уже применены. Точные версии и контрольные суммы находятся в docs/applied-migrations.json. Не применяйте их повторно вручную поверх существующей схемы. Конфигурация supabase/config.toml задаёт локальную среду и не меняет удалённые настройки Auth.

Настройте подтверждение почты, SMTP, разрешённые адреса сайта и восстановления пароля, лимиты Auth и CAPTCHA до публичного открытия. Проверка утёкших паролей пока отключена в настройках Supabase. Настоящий мэр назначается доверенным администратором по проверенному UUID Auth, а не никнейму. Автоматически назначать первого зарегистрированного пользователя мэром нельзя. Тестовые аккаунты необходимо заблокировать и отозвать их сеансы перед публичным запуском; не удаляйте тестовую историю без отдельного решения.

npm test запускает 22 проверки денежных преобразований, компонентов, гонок переключения чатов и целостности статического комплекта. npm run check проверяет синтаксис модулей. SQL-наборы tests/*.integration.sql предназначены только для пустой тестовой среды и используют ROLLBACK. Python-наборы tests/http.integration.py, tests/storage.integration.py, tests/publishing.integration.py, tests/education.integration.py, tests/payroll.integration.py tests/rentals.integration.py и tests/tasks.integration.py выполняют реальные запросы с JWT четырёх заранее созданных QA-аккаунтов. Укажите KAPANI_QA_CREDENTIALS с абсолютным путём к закрытому JSON вне репозитория. Структура элемента содержит id, email, password, username, role. Никогда не включайте этот файл в public, архив или систему контроля версий. HTTP-наборы сохраняют фикстуры и не удаляют данные. Результаты прошедших проверок сохраняются в tests/*-results.json.

Все суммы в К₽ являются условной валютой Капани. Минимальные единицы хранятся как bigint. Эмиссия отображается отдельным отрицательным счётом источника, а не скрытым увеличением кошельков. Проценты округляются вниз до минимальной единицы, рассчитываются по состоянию журнала на конец московских суток и ограничиваются настройкой. Cron каждый час восстанавливает пропущенные завершённые периоды. Подписки проверяются по серверному времени; автоматическое продление пока отсутствует.

Публичный запуск и внешние интеграции ещё не выполнены. Полное исходное техническое задание шире текущего результата. Не используйте эту контрольную точку как заявленный готовый сервис.

Функция входа находится в supabase/functions/kapani-login и уже развёрнута в новом проекте. При переносе сначала примените миграции, затем разверните kapani-login, сохранив verify_jwt=false именно для этой точки входа — она сама проверяет учётные данные через Auth. Функция prepare_login недоступна anon и authenticated. Серверные секреты предоставляет среда Supabase, в браузер их не копировать.

Для карты настройте config.mapTiles и config.mapAttribution только для разрешённого вам провайдера, добавьте его домен в img-src политики index.html. Начальный центр config.mapCenter соответствует обзору Елецкого района, точные публичные объекты заполняет мэрия. Тайлы не входят в офлайн-кэш и не скачиваются массово. Проверка текущего облачного браузера показала блокировку со стороны OpenStreetMap, поэтому фоновая карта по умолчанию выключена.

Дополнительные реальные проверки находятся в tests/commerce.integration.py, tests/login.integration.py и tests/map.integration.py. Изолированный браузерный стенд карты создаёт tests/map-browser-build.mjs; public/__qa не должен публиковаться. Он подменяет API пустыми тестовыми ответами и предназначен только для проверки отображения.

Такси использует Edge Function kapani-route и серверный жизненный цикл поездки. Разверните функцию с verify_jwt=false; она самостоятельно проверяет JWT через Auth. В секретах Edge задайте KAPANI_OSRM_BASE_URL с HTTPS-адресом совместимого дорожного провайдера, проверьте настоящий маршрут и только затем включите config.routingConfigured. Пока провайдер не задан, расчёт закрыт и цены не создаются. Настройка клиента не отменяет серверную проверку. Сервер резервирует оплату, предлагает поездку свободному водителю, проверяет последовательность статусов и распределяет оплату либо возвращает резерв. Геолокация передаётся только после отдельного согласия водителя.

Taxi SQL-набор tests/taxi.integration.sql допускает только технические QA-аккаунты и откатывает изменения. HTTP-набор tests/taxi-http.integration.py требует KAPANI_QA_CREDENTIALS и KAPANI_QA_TAXI_QUOTE с заранее созданной явно синтетической тестовой котировкой. Не запускайте эти проверки в базе с реальными жителями. Маршрут тестовой фикстуры не доказывает доступность дорожного провайдера.
